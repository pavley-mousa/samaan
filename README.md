# Samaan — متجر الأقمشة والجلاليب

منصة عربية مخصصة لبيع الأقمشة بالمتر، والجلاليب الجاهزة والتفصيل، للأفراد وتجار الجملة.

## ما تم تنفيذه في هذه النسخة

- واجهة عربية RTL متجاوبة، مع تسجيل ودخول وتأكيد البريد.
- قاعدة بيانات PostgreSQL مستضافة على Supabase، مع نموذج Prisma متوافق معها.
- صلاحيات المدير مفحوصة داخل خادم NestJS، وليس بمجرد إخفاء الأزرار.
- كتالوج منتجات حقيقي من قاعدة البيانات، وبحث وفلترة حسب نوع المنتج.
- صفحة تفاصيل لكل منتج مع الألوان والمقاسات والأسعار والكميات المتاحة.
- إدارة المنتجات وإضافة المتغيرات (لون/مقاس) وتحديث المخزون من لوحة المدير.
- سلة تسوق محفوظة محليًا في المتصفح.
- تسجيل طلبات الدفع عند الاستلام مع عنوان التوصيل، وإعادة التحقق من الأسعار والمخزون على الخادم.
- صفحة لحساب العميل وسجل طلباته، ولوحة لتحديث حالة الطلبات وإرجاع المخزون تلقائيًا عند إلغاء طلب غير ملغى.
- سياسات RLS على جداول Supabase، وجداول المصادقة المخصصة محجوبة عن وصول العملاء المباشر.

> هذه نسخة تطوير أولى وليست إصدارًا نهائيًا للإنتاج. لم يتم بعد ربط مزود شحن، أو بوابة دفع إلكتروني، أو خدمة رفع صور، أو تدفقات أسعار الجملة والكوبونات والتقييمات التفصيلية. الشحن يظهر حاليًا كرسوم غير محددة، ولا تُضاف رسوم تلقائية إلى الطلب.

## التقنيات

- الواجهة: Next.js + React + TypeScript
- الخادم: NestJS + TypeScript
- قاعدة البيانات: PostgreSQL مستضافة على Supabase
- ORM: Prisma
- لا يحتاج المشروع إلى Docker أو تثبيت توزيعة Linux.

## إعداد المشروع على Windows

1. فك ضغط المشروع وافتح مجلد `samaan` في VS Code.
2. انسخ `.env.example` إلى ملف جديد اسمه `.env` في جذر المجلد.
3. افتح لوحة مشروع Supabase باسم `Samaan` ثم اضغط **Connect** وانسخ سلسلة PostgreSQL من خيار **Session pooler**. ضع السلسلة كاملة في `DATABASE_URL`. لا تخمّن اسم المضيف أو المستخدم.
4. أنشئ سرًا عشوائيًا قويًا لـ `JWT_SECRET` (32 حرفًا على الأقل). اترك إعدادات SMTP فارغة أثناء التطوير المحلي فقط، أو عبئها بإعدادات مزود البريد عند الحاجة لاختبار إرسال رسائل حقيقية.
5. افتح Terminal داخل مجلد `samaan` وشغّل:

   ```powershell
   npm install
   npm run db:generate
   npm run db:validate
   ```

6. حدّد بريد المدير الأول وكلمة مروره في `.env` داخل `BOOTSTRAP_ADMIN_EMAIL` و`BOOTSTRAP_ADMIN_PASSWORD`. كلمة المرور لا تقل عن 14 حرفًا. لا ترفع `.env` إلى GitHub ولا تشارك كلمة المرور.
7. شغّل `npm run admin:create` مرة واحدة لإنشاء حساب المدير الأول.
8. شغّل `npm run dev` وافتح `http://localhost:3000`.

قاعدة بيانات Supabase لهذا المشروع تم إعدادها بالفعل وتحتوي جداول المتجر والتصنيفات الأولية. **لا تشغّل `prisma migrate dev` على قاعدة البيانات الحالية**؛ سجل التغييرات محفوظ ضمن `supabase/migrations` وتتم إدارة تغييرات مخطط Supabase بترحيلات SQL. عنوان قاعدة البيانات وكلمة المرور الحقيقية لا يوضعان في المستودع.

## فحص تسجيل الدخول والبناء

- أنشئ حساب عميل واختبر تأكيد البريد ثم تسجيل الدخول.
- سجّل الدخول بحساب المدير الذي أنشأته عبر `npm run admin:create`.
- من لوحة المدير أضف منتجًا ثم أضف لونًا/مقاسًا ومخزونه.
- افتح المتجر بحساب العميل، جرّب البحث وصفحة المنتج والسلة، ثم أنشئ طلبًا تجريبيًا بالدفع عند الاستلام.
- من لوحة المدير غيّر حالة الطلب. جرّب إلغاءه وتأكد من عودة المخزون.
- عند تجهيز بيئة تسمح بتنزيل حزم npm، شغّل `npm run typecheck` وعمليات البناء لكل من الواجهة والخادم قبل النشر.

## هيكل المجلدات

- `apps/storefront`: واجهة المتجر ولوحة العميل والمدير.
- `apps/api`: API المصادقة والمنتجات والمخزون والطلبات.
- `apps/api/prisma/schema.prisma`: نموذج قاعدة البيانات المتوافق مع المخطط الحالي.
- `supabase/migrations`: سجل SQL الخاص بمخطط قاعدة البيانات.
- `docs`: مواصفات المنتج والمعمارية والأمان وخطط الاختبار.

## رفع المشروع إلى GitHub (اختياري)

بعد التحقق من التشغيل، يمكن رفعه كمستودع خاص من PowerShell باستخدام السكربت الموجود في `scripts/publish-to-github.ps1`. لا ترفع ملف `.env` أو أي مفاتيح/كلمات مرور.
