# متطلبات الأمان

## المصادقة والحسابات
- تخزين كلمات المرور باستخدام خوارزمية مخصصة لكلمات المرور (مثل Argon2id أو إعداد آمن معتمد من الإطار).
- تفعيل التحقق من البريد قبل تفعيل الحساب وفق تدفق واضح.
- تحديد معدل محاولات الدخول وإعادة تعيين كلمة المرور.
- رسائل الخطأ لا تكشف هل البريد مسجل في مسار استعادة كلمة المرور.
- إنشاء المدير الأول عبر seed أو أداة تشغيل محمية وأسرار بيئة؛ لا يوجد خيار `admin` في التسجيل.
- مراجعة دور الحساب من قاعدة البيانات/الخادم، لا من اسم البريد وحده ولا من بيانات يرسلها المتصفح.

## الجلسة والصلاحيات
- ملفات ارتباط آمنة و`HttpOnly` و`Secure` في الإنتاج، وسياسة `SameSite` مناسبة.
- حماية CSRF حسب أسلوب المصادقة، وضبط CORS إلى أصول موثوقة.
- فحص دور المدير في كل API إداري. إخفاء الزر في الواجهة لتحسين التجربة فقط.
- العميل يقرأ طلباته وبياناته فقط.
- تغييرات الأدوار والصلاحيات محمية وتُسجل.

## الأسعار والطلبات والمخزون
- حساب الأسعار والخصومات ورسوم الشحن على الخادم.
- إعادة التحقق من صلاحية سعر الجملة عند إتمام الطلب.
- معاملات قاعدة بيانات تمنع بيع كمية غير متاحة.
- مفاتيح idempotency للأحداث التي قد يعاد إرسالها، خصوصًا الدفع.
- سجل تدقيق للتعديلات الإدارية على السعر والمخزون والطلبات.

## الملفات والبيانات
- فحص نوع الملف وحجمه عند رفع الصور، وتغيير أسمائه وتخزينه بطريقة آمنة.
- الصور المرجعية ومرفقات العملاء لا تكون عامة تلقائيًا.
- عدم تسجيل كلمات المرور أو رموز الجلسات أو أسرار التكامل أو بيانات الدفع.
- نسخ احتياطي واختبار الاسترجاع، وإدارة الأسرار خارج Git.
- HTTPS في الإنتاج وتحديث الاعتمادات وفحص الثغرات دوريًا.
