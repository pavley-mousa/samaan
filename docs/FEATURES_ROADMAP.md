# خريطة ميزات Samaan

هذا المستند هو سجل الميزات المعتمد للمشروع حتى لا تختفي متطلبات العمل بين جلسات التطوير. حالة "موجود جزئيًا" تعني أن النموذج أو شاشة أولية موجودة لكن دورة العمل الكاملة غير مكتملة.

## الموجود حاليًا وفق مراجعة الكود

- [x] واجهة عربية RTL وصفحات الرئيسية والمنتج وتسجيل/دخول والتحقق من البريد والسلة وإتمام الطلب وحساب العميل ولوحة الإدارة.
- [x] حسابات عميل ومدير، تخزين كلمات المرور بتجزئة bcryptjs، وتأكيد البريد عند توفر SMTP.
- [x] كتالوج منتجات وتصنيفات، بحث حسب الاسم/الوصف/الخامة ونوع المنتج.
- [x] أنواع المنتجات الأساسية: قماش بالمتر، جلابية جاهزة، جلابية تفصيل، وإكسسوارات.
- [x] متغيرات المنتج للون والمقاس وSKU وسعر اختياري ومخزون.
- [x] سلة محلية على المتصفح وطلب دفع عند الاستلام.
- [x] إعادة حساب سعر الطلب والتحقق من المخزون على الخادم داخل معاملة قاعدة بيانات.
- [x] سجل طلبات العميل ولوحة أولية لإدارة المنتجات والطلبات.
- [x] نموذج قاعدة بيانات أولي للمفضلة وطلبات التفصيل ومستويات أسعار الجملة، لكن ليست كل هذه الوظائف متاحة للمستخدم بعد.
- [x] حاويات Supabase Storage أُنشئت سابقًا، لكن تكامل الرفع والتحقق من الملفات لم يكتمل.
- [x] الكتالوج متاح للزوار دون تسجيل بعد تحديث مسارات القراءة العامة؛ يجب التحقق من نشر هذا التغيير.

## P0 — أساس آمن قبل البيع الحقيقي

- [ ] إعداد `DATABASE_URL` حديث وآمن من Supabase وتخزينه كـSecret في الاستضافة، بعد تدوير كلمة مرور قاعدة البيانات المكشوفة سابقًا.
- [ ] إعداد SMTP حقيقي واختبار رسائل التحقق؛ لا نضع بيانات وهمية أو نعيد رموز التحقق في بيئة الإنتاج.
- [ ] اختبار نشر API وربط الواجهة به عبر مسار same-origin، ثم اختبار الكوكيز وتسجيل الدخول والخروج وCORS.
- [ ] إزالة أي fallback لمفتاح JWT ضعيف، والتأكد أن الإعداد الفعلي يقرأ الـSecret الصحيح.
- [ ] صفحة سياسة الخصوصية والشروط والاستبدال والاسترجاع وبيانات التواصل.
- [ ] سجل تدقيق للأعمال الإدارية الحساسة، وسجل تاريخ لحالات الطلب.
- [ ] تحقق من الطلبات المتكررة، تنافس المخزون، وإلغاء الطلب مرة واحدة فقط.
- [ ] فحص الصلاحيات على كل مسارات الإدارة وملكية الطلبات وطلبات التفصيل.

## P1 — ميزات تجارية أساسية

### الكتالوج والصور
- [ ] رفع صور المنتج مباشرة إلى Supabase Storage مع التحقق من النوع والحجم وتوليد اسم آمن.
- [ ] فصل صور المنتجات العامة عن الصور المرجعية الخاصة بطلبات التفصيل.
- [ ] معرض متعدد الصور، صورة رئيسية، ترتيب الصور ونص بديل.
- [ ] تصنيفات متداخلة وفلترة حسب الخامة والموسم واللون والمقاس والنطاق السعري والتوفر.
- [ ] ترقيم صفحات/تحميل تدريجي وفرز حسب الأحدث والسعر والأكثر مبيعًا.

### طلبات التفصيل والجلابيب
- [ ] إنشاء طلب تفصيل من صفحة المنتج أو صفحة مستقلة.
- [ ] مقاسات متعددة مع وحدات قياس واضحة وملاحظات العميل وصورة تصميم مرجعية خاصة.
- [ ] دورة حالات للطلب: جديد، قيد المراجعة، بانتظار عرض السعر، عرض السعر مرسل، موافق عليه، قيد التنفيذ، جاهز، تم التسليم، مرفوض/ملغي.
- [ ] إرسال عرض سعر ومدة متوقعة للعميل، مع موافقة صريحة على السعر قبل التحويل إلى طلب نهائي.
- [ ] صفحة حساب العميل لمتابعة الطلبات والقياسات والتحديثات.
- [ ] لوحة الإدارة لمراجعة الطلبات وتغيير حالاتها وإضافة الملاحظات وعرض الصورة الخاصة بشكل مصرح فقط.

### أسعار الجملة
- [ ] ملف تاجر جملة وطلب انضمام بمراجعة المدير وحالات: قيد المراجعة، مقبول، مرفوض، موقوف.
- [ ] مستويات أسعار كمية لكل منتج/متغير، مع حدود كمية واضحة وأولوية سعر محددة.
- [ ] تطبيق السعر المناسب على الخادم فقط عند عرض الأسعار وتأكيد الطلب.
- [ ] إظهار حالة اعتماد الجملة والأسعار في حساب العميل وسلة الشراء.
- [ ] قواعد الحد الأدنى للطلب ومجموعات المنتجات أو الاستثناءات إن قررتها الإدارة.

### المخزون والتوصيل
- [ ] سجل حركات المخزون: استلام، بيع، إرجاع، تسوية، تلف؛ لا نكتفي بتغيير رقم المخزون دون سجل.
- [ ] تاريخ حالات الطلب ومن قام بكل تغيير.
- [ ] رسوم شحن محددة حسب المنطقة/المحافظة/قيمة الطلب أو إعداد إداري واضح بدل رسوم مبهمة.
- [ ] بيانات الشحنة وشركة الشحن ورقم التتبع وحالات الشحن.
- [ ] إشعارات للعميل عند تأكيد الطلب والشحن والتسليم أو تغيّر حالة التفصيل.
- [ ] سياسة إلغاء وإرجاع واستبدال واضحة، وإعادة المخزون عبر معاملة آمنة.

## P2 — التسويق وتجربة العميل

- [ ] مفضلة/قائمة رغبات محفوظة بالحساب.
- [ ] كوبونات وخصومات: صلاحية زمنية، حد استخدام، حد أدنى، نطاق المنتجات، ومنع التكرار.
- [ ] تقييمات ومراجعات للمنتجات مع قصر التقييم الموثق على المشتريات المؤهلة ومراجعة إساءة الاستخدام.
- [ ] استعادة كلمة المرور عبر رمز أحادي الاستخدام مخزن كبصمة، ينتهي ويُستهلك مرة واحدة.
- [ ] إدارة عدة عناوين للعميل واختيار العنوان الافتراضي ونسخ بيانات العنوان داخل الطلب.
- [ ] حفظ السلة للمستخدم المسجل ومزامنتها مع السلة المحلية دون تكرار البنود.
- [ ] البحث المتقدم وحفظ تفضيلات الفلاتر.
- [ ] مركز إشعارات داخل الحساب مع حالة الإرسال.
- [ ] تصدير الطلبات إلى CSV أو تقرير إداري حسب الفترة والحالة.
- [ ] إدارة محتوى البنرات والعروض ورسائل الصفحة الرئيسية من لوحة الإدارة.

## P3 — التوسع بعد استقرار الطلبات

- [ ] بوابة دفع إلكتروني مصرية مع التحقق من Webhooks وتكرار الأحداث ومطابقة المبلغ والعملة.
- [ ] عمليات رد الأموال والتسويات المالية.
- [ ] تقارير المبيعات والمنتجات الأكثر طلبًا والمخزون منخفض الكمية وتجار الجملة.
- [ ] أكثر من مخزن ومواقع مخازن عند الحاجة.
- [ ] تكامل موثق مع مزودي الشحن بدل ربط غير رسمي.
- [ ] تحسينات SEO وبيانات المنتجات المنظمة وخرائط الموقع والأداء.
- [ ] اختبارات آلية للتسجيل وتأكيد البريد والطلبات والصلاحيات والتفصيل والجملة والكوبونات.
- [ ] نسخ احتياطي دوري واختبار استرجاع، ومراقبة أخطاء وتنبيهات تشغيل.

## قواعد التنفيذ

1. ننفذ ميزة صغيرة قابلة للاختبار في كل مرة؛ لا نضيف كل الوحدات دفعة واحدة.
2. أي سعر أو خصم أو مخزون أو حالة دفع أو صلاحية يقررها الخادم.
3. الأسرار لا تُرفع إلى GitHub ولا تُكتب داخل الواجهة.
4. كل تغيير لمخطط قاعدة البيانات له migration واضح قابل للتتبع.
5. لا تُعلن أي ميزة مكتملة حتى ينجح البناء واختبار المسار الفعلي.
6. لا يتم تفعيل دفع إلكتروني أو استضافة تشغيلية تجارية قبل إكمال اختبارات الأمان والشراء.

## ترتيب التنفيذ المقترح

1. إصلاح النشر والاتصال الآمن بالـAPI وSupabase والبريد.
2. إتاحة تصفح المنتجات للزائر وسلة لا تتطلب تسجيلًا حتى لحظة إتمام الشراء.
3. رفع صور المنتجات الآمن.
4. دورة طلب التفصيل الكاملة.
5. طلب اعتماد تاجر الجملة وتطبيق أسعار الجملة.
6. المفضلة والكوبونات والتقييمات واستعادة كلمة المرور.
7. الشحن والتتبع والإشعارات، ثم بوابة الدفع والتقارير.
